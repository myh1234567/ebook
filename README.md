# Ebook 工作台

一个 tkinter 窗口，三个页签：

| 页签 | 做什么 |
|---|---|
| **助眠视频** | txt 文案 → 慢速朗读 → 背景视频循环 → 配乐垫底 → ffmpeg 成片 → 上传 YouTube |
| **小说改编** | 中文小说 → 跨文化改编成英文小说 → 产出 Amazon KDP 全套出版物料 |
| **KDP 上架** | 物料预检 → 字段一键复制 → Chrome 自动填表 |

三个页签共用底部的进度条和日志，同一时间只跑一个任务，「停止」对三者都生效。

## 跑起来

```bash
brew install ffmpeg              # 已装可跳过
.venv/bin/pip install -r requirements.txt
.venv/bin/python main.py
```

### 助眠视频

界面里选好「文案 txt / 背景视频 / BGM 音频」，点**生成视频**。
`assets/` 里已经放了一段测试视频和一段测试配乐，直接点生成就能跑通全流程，
确认没问题后把它们换成你自己的素材即可。

三个按钮的用法，按这个顺序省时间最多：

1. **试听语音** —— 一句话，秒出。用来定音色、参考音频、语速。
2. **生成音频** —— 只跑 TTS + 混音，不渲画面，产出 m4a 并自动打开播放。
   长文案渲一遍画面很贵，先把声音听满意了再往下走。
3. **生成视频** —— 完整成片。

### 小说改编

选中文小说 txt，填好改编设定（目标国家、年代、类型）和书籍信息，填上大模型
API Key，点**开始改编**。产出落在 `输出目录/书名/` 下：

```text
01_English_Manuscript.docx   完整英文母稿（Heading 1 章标题，Kindle 能自动生成目录）
02_Publishing_Copy.docx      KDP 出版资料包
03_Publishing_Copy.txt       同上的纯文本版，KDP 页签就是读这个文件
04_Internal_Synopsis.docx    内部全剧情梗概（含剧透）
05_Ebook_Cover.png           1600x2560 排版封面
08_Adaptation_Bible.md       人物映射、世界设定、术语表、时间线
09_Image_Prompts.txt         封面与海报的英文生图提示词
10_Quality_Check_Report.md   质检核验报告
```

改编不是翻译：人名、地名、官制、货币、社交礼仪全部按目标年代重建，只有故事的
因果链不许动。规则全文在 `.agents/skills/novel-adaptation-kdp/SKILL.md`。

> **离线演示模式**勾上就不调 API，每一章都填同一段占位英文。它只用来看排版和交付
> 结构对不对，产出的不是能拿去出版的稿子。

清单里的 `06_Promotional_Poster.png` 和 `07_Cover_Art_No_Text.png` 目前不生成，
提示词在 `09_Image_Prompts.txt` 里，得自己拿去生图。

### KDP 上架

改编跑完会自动把项目目录填进这个页签。

1. **读取并预检** —— 解析元数据，按 KDP 规则查书名长度、简介 4000 字符上限、
   关键词槽位、正文和封面文件在不在，结果打在日志里。
2. **复制简介 HTML / 复制 7 个关键词** —— 进剪贴板，手动填表时用。
3. **用 Chrome 自动填表** —— Selenium 打开 KDP，把书名、副标题、作者、简介、
   7 个关键词填进新书草稿的第 1 步。**不会替你点发布**，浏览器一直开着；分类、
   定价、正文 docx 和封面图仍要自己在浏览器里完成。

第一次会弹出 Chrome 让你手动登录 + 2FA，凭据存在 `~/.kdp_chrome_profile`
（或你自己指定的 Chrome 用户目录），之后自动复用。

## 各部分在哪

| 文件 | 作用 |
|---|---|
| `main.py` | tkinter 界面：三个页签 + 共用的日志/进度/后台线程 |
| `config.py` | 全部可调参数 + `settings.json` 持久化 |
| `tts.py` | 文案切段 + 朗读（两个引擎的分派在这里），段间插静音 |
| `clone_tts.py` | F5-TTS 声音克隆 |
| `video.py` | 背景视频规范化、混音、成片的 ffmpeg 命令 |
| `pipeline.py` | 视频四步流程编排 |
| `uploader.py` | YouTube 上传（需要凭证才启用） |
| `novel_adapter.py` | 章节切分、改编档案、逐章改编、出版元数据、交付打包 |
| `kdp_formatter.py` | docx 排版与封面图生成 |
| `kdp_uploader.py` | KDP 元数据解析、上架预检、Selenium 自动填表 |

## 文案格式

纯 txt，**用空行分段**。每个空行 = 一次段落停顿（默认 2.5 秒），
这是助眠节奏的主要控制手段。段落太长会自动按句号再切开。
参考 `scripts/sample.txt`。

## 声音克隆（用你自己的声音念）

界面「引擎」切到**克隆声音**，选一个参考音频，就会用那个人的音色念文案。

```bash
.venv/bin/pip install f5-tts     # 会带 torch，约 3-4GB；首次生成再下约 1.5GB 模型
```

**参考音频怎么准备**（这一步决定了成品质量，比任何参数都重要）：

- **10~15 秒就够**，太长反而不好。程序会自动从「取样起点」往后截 12 秒。
- **必须是干净人声**：无背景音乐、无混响、无杂音。
- **语气要对**。zero-shot 克隆不只学音色，连**说话风格一起学**。
  你给它一段正常语速的朗读，它就用正常语气念；
  给它一段本来就轻柔、缓慢、气声多的参考，助眠感会好一个档次。
  所以最好专门录一段"哄睡语气"的参考音频，而不是随便找段说话。
- **参考文本**填参考音频里念的那句话，能明显提升稳定性。留空会自动转写，
  但要多下一个语音识别模型。
- 只克隆你有权使用的声音。

**慢放方式**（只对克隆引擎有效，界面上可切）：

- **引擎生成**（默认）：把 `speed` 传给 F5-TTS，让模型**本来就用慢语速去生成**。
  实测 speed=0.75 时长精确变成 1.33 倍，耗时不变。声音是慢着说出来的，更自然。
- **后期拉伸**：正常生成后用 ffmpeg `atempo` 做时间拉伸（保持音高不变）。
  更可控，但拉伸比例大了（比如 0.75）人声会发涩发硬。

觉得声音「生硬」时，先切到引擎生成试试。界面上「语速 %」对两个引擎、两种方式
都是同一个含义，底下实现不同而已。

另外要知道：**克隆会把参考音频的语速一起学走**。参考念得慢，克隆出来就慢，
再叠「语速 %」会更慢。日志里会打印实际的「字/秒」，低于 3 会提示。

**速度**：模型只加载一次然后常驻，之后每段大约实时速度。
30 分钟的旁白大概要跑 20-40 分钟，建议先用「试听语音」把参考音频选定了再生成。

## 参数怎么调

- **语速 -25%**：助眠的合适区间大概 -20% ~ -35%，再慢会不自然。
- **音调 -2Hz**：压低一点更催眠。
- **段落停顿 2.5 秒**：想更慢可以加到 4 秒。
- **BGM 音量 0.12**：这是**相对人声**的比例（0.12 ≈ 比人声低 18dB），
  不是乘 BGM 文件的原始音量。所以换一首响度不同的 BGM，人声和背景的比例不会变。
- **接缝淡化 3 秒**：只在背景视频比成片短、需要循环时才生效。
- **帧率 0**：跟随源视频，建议别改。30fps 的素材硬转 24fps 会每 5 帧丢 1 帧，
  平移镜头上明显发顿——看起来就像"和原视频对不上"。

## 响度

旁白会先归一化到统一电平（平均 -23 dBFS，峰值不越过 -1.5 dBFS），再摆 BGM。

这一步是必须的：**F5-TTS 会把输出响度缩放回参考音频的响度**，参考录音录得轻，
克隆出来的旁白就跟着轻——实测参考 -33.1dB、生成的旁白 -32.6dB，几乎一模一样。
不归一化的话，成片响度完全随参考音频漂移，手机上正常音量根本听不清。

用的是静态增益，不是动态压缩：段落之间的静音不会被抬起来（那会变成恼人的底噪起伏）。

## 配乐

选一个 mp3（wav / m4a / flac 也行）。**不够长会自动循环**铺满整条成片，
并按「淡入淡出 秒」在首尾各做一次淡化。不选就只有旁白。

## 背景视频

选一个 mp4（mov / mkv / webm 也行），它会循环播放铺满整条成片。
源片的音轨会被丢掉，声音只来自旁白和 BGM。

竖屏、4K、HEVC、可变帧率的片子都能直接喂进来——程序会先规范化成
1080p / 固定帧率 / yuv420p，超出画幅的部分居中裁切。

**接缝处理**：视频比成片短时才会循环。这时把尾部 3 秒和开头交叉淡化，
接缝两侧正好落在同一帧，所以看不出跳变（成片实测：接缝处的帧间差异
和视频自身的正常帧间差异同一量级）。视频本来就够长则直接截断，不做任何处理。

## 为什么渲染这么快

背景视频**只编码一次**，再用 `-stream_loop` 无损循环到音频长度，
成片阶段视频流全程 `-c:v copy`。所以做一小时的成片，编码量只有背景视频本身那么长。

而且是先混音拿到总时长、再准备画面：你给一个 1 小时的素材但成片只要 5 分钟时，
不会白编码那用不上的 55 分钟。

## 之后要接 AI 生成

背景视频和配乐现在都是直接给一个文件路径，所以接 AI 生成不用改流水线：
生成完落盘，把路径填进去（或在 `pipeline.generate()` 里把 `s.video_path` /
`s.bgm_path` 换成生成函数的返回值）即可。

- **配乐** → MusicGen / ElevenLabs Music
- **画面** → Veo / Runway / Kling 之类，输出 mp4

## 踩过的坑

**MPS 多线程崩溃**（已在 `clone_tts.py` 里修掉，记下来防止以后升级踩回去）：
文本长到被 F5-TTS 切成 2 个以上 batch 时，它会用 `ThreadPoolExecutor` 并发推理，
而 PyTorch 的 MPS 后端不支持多线程并发提交，会触发 Metal 断言
`A command encoder is already encoding to this command buffer` 并**直接杀掉整个进程**。
修法是把那个 executor 限成单 worker（它本来就按提交顺序收结果，串行不改变输出）。
升级 f5-tts 后如果日志里出现「没能给 F5-TTS 打串行补丁」，就是这个补丁失效了。

**PYTHONHASHSEED 越界**（同样已修）：F5-TTS 不传种子时取 `random.randint(0, sys.maxsize)`，
再写进 `os.environ["PYTHONHASHSEED"]`，而那个变量上限是 2³²-1。超了之后
**本进程再也起不了任何 Python 子进程**。所以 `clone_tts.py` 里显式传了合法范围内的种子。

## 上传 YouTube

`uploader.py` 已经写好完整上传逻辑，但要先备齐两样东西才会启用：

1. `pip install google-api-python-client google-auth-oauthlib`
2. Google Cloud Console → 启用 YouTube Data API v3 → 建 OAuth 客户端 ID（桌面应用）
   → 下载 JSON 改名 `client_secret.json` 放到项目根目录

首次上传会弹浏览器授权，token 存 `token.json`。默认上传为**私享**。
注意配额：一次上传约 1600 点，默认每天 10000 点，也就是一天 6 条左右。
